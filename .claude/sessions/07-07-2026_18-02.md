# Session summary

## Tasks completed
- **Clock controls**: `bpm`/`loopLengthBeats` are now runtime-mutable (`NLLCClock.setLoopLengthBeats`, alongside the existing glitch-free `setBpm`), exposed via a new `/clock [bpm=] [num_beats=]` top-level command (no-params reports current values).
- **Events start empty**: removed `placeholderEvents()` from `oscsynth.js`/`sampler.js` — a fresh synth is silent until authored. Added generic `add_event`/`clear_events` params to `channelCommand` (works on any synth type via the `NLLCSynth` base class): `/track_1 add_event beat= pitch=|degree= velocity= duration=`.
- **Harmony hook (deferred real logic, per explicit user decision)**: new `harmony.js` — `createHarmonyContext()` (`{root, scale}`, chromatic by default) and `resolveDegree(harmony, degree)`. `NLLCEvent` gained an optional `degree` field alongside `pitch`; `NLLC` constructs one shared `this.harmony` and threads it into every synth via `createSynth`; `oscsynth.trigger()` resolves `degree` against it **at trigger time** (not authoring time), so a future key/scale-changing command will retune already-scheduled patterns live. `sampler` ignores `degree` (pitch = slot index there).
- **Ramp syntax**: `parseCommand` now accepts a trailing duration on any value (`gain=0 3` = 3 seconds, `gain=0 4b` = 4 beats), producing `{value, duration, unit}` instead of a scalar. Wired into `gain=`/`pan=` (through the existing gain taper) and generically into every processor param.
- **`at=beat` / `at=cycle` scheduling**: ramps default to starting immediately; `at=beat`/`at=cycle` defers the start to `clock.nextBeatTime()`/`nextCycleTime()` (new clock methods, alongside `currentBeat()`). An unrecognized `at=` value warns and falls back to "now" rather than erroring.
- **Multi-command lines**: `executeCommand` now splits one submitted line on every `/name` occurrence (`splitCommands`) and dispatches each segment together, e.g. `/track_1 gain=0 8 /reverb wet=0.9 6b` — both run in the same call stack, scheduled off the same instant.
- **Ramp-curve consolidation**: extracted a single private `applyRamp(param, time, endTime, from, to, curve)` in `automation.js` that both `scheduleAutomationEvent` (loop-position pattern automation, used by the clock) and the renamed/generalized `scheduleRamp(audioContext, param, from, to, durationSeconds, {startTime, curve})` (one-off console ramps) call into — done specifically so the two curve implementations (which had already drifted — `scheduleImmediateRamp` was missing the `"target"` curve) can't diverge again. The two entry points were deliberately *not* merged into one, since "ramp starting right now" doesn't have a natural loop-relative beat to attach to.
- **Full documentation pass** against `.claude/tasks/write_documentation.md`: updated `docs/user/` (commands.md, objects.md, tutorial.md), `docs/dev/` (architecture.md, source-overview.md, creating-a-synth.md, creating-a-processor.md, adding-commands.md), and `docs/llm/` (overview.md, building-synths.md, building-processors.md, adding-commands.md) to reflect all of the above — removed every stale "seeds a placeholder pattern" claim, documented the new command surface, and fixed a doc example (`adding-commands.md`'s illustrative `bpm:` command sketch) that had gone stale by becoming a real feature. Root/docs README.md reviewed, no changes needed. Code comments were written inline as each file changed (not a separate pass).
- Verified throughout with `svelte-check` (clean, 0 errors/warnings across all changes) and multiple live headless-browser smoke tests (via a manually-driven Playwright script, since no project `run` skill exists yet and `chromium-cli` wasn't installed — used the cached `npx` playwright package + cached Chromium binary) exercising `/clock`, ramps (verified exact beat→seconds math at custom bpm), multi-command lines, `add_event`/`clear_events`, `at=beat`/`at=cycle`, and `/start` actually ticking the scheduler through several loops with mixed `pitch`/`degree` events — no console errors in any run.

## Project overview
NLLC is a SvelteKit + Web Audio live-coding music environment. Core DSP/scheduling engine in `src/lib/scripts/nllc-src/`: `NLLC` (top-level owner: audioContext, clock, master, tracks, processors, `SYNTH_TYPES`/`PROCESSOR_TYPES` registries, and now a shared `harmony` context), `NLLCClock` (lookahead scheduler over "units"; bpm and loop length are both runtime-mutable now), `NLLCChannel`/`NLLCTrack`, `NLLCSynth` → `NLLCOscSynth`/`NLLCSampler` (both now start with empty event lists — no self-seeded placeholder patterns), `NLLCProcessor` → `NLLCReverb`/`NLLCDelay`, `NLLCEvent`/`NLLCAutomationEvent` as the two schedulable data shapes (event now also carries an optional `degree`), `taper.js`, and the new `harmony.js`. `commands.js` is the closure-based `/name key=val` router — now considerably richer: clock control, manual event authoring, ramp syntax with deferred scheduling, and multi-command-per-line dispatch, all layered onto the existing pattern without disturbing it. The Svelte UI is unchanged in shape (still a thin, polled read/write view onto the live `NLLC` object), except `+page.svelte`'s demo bootstrap now explicitly calls `addEvent` since synths no longer self-seed. `Ollama()` remains an empty, unwired stub. `docs/` (user/dev/llm tiers) is now in sync with all of today's engine changes.

## Open questions and next steps
- Wire up `Ollama()` to translate natural language into the command vocabulary — the command surface is now considerably richer (clock, events, ramps, scheduling hints), making it a better/closer target than at the start of this session.
- Cycle-based/recurring generation (an `onCycle(cycleIndex)` hook on the clock's "unit" contract, throttled per-generator for every-N-cycles) was explicitly deferred this session at the user's request — still a good, low-risk extension point when picked back up, since it follows the same duck-typed pattern the clock already uses for `events`/`automation`/`trigger()`.
- Rhythm-context tooling (a shared subdivision/grid/swing context analogous to `harmony.js`, plus pattern-generator helpers like euclidean rhythms or step-string parsers) was floated but not built — deferred alongside cycle-based generation since the two were tightly coupled in the original ask.
- Real harmonic logic: `nllc.harmony` is currently a passthrough (chromatic scale, `degree` ≈ semitone offset). No `/harmony` command exists yet to change `root`/`scale` at runtime — building one (plus real scale/chord tables) is the natural next step now that the trigger-time-resolution hook is in place.
- Sampler-specific controls remain unbuilt: no slot inspection/rename/reassignment from the console, no per-voice gain/pitch, no polyphony limit.
- No processor-reordering command yet (only display of current order).
- Synth-level runtime params (e.g. `NLLCOscSynth.waveform`) still aren't exposed through `channelCommand` the way processor params are — only settable via `/add_track synth=... waveform=...` at creation time. Flagged in both `docs/dev/creating-a-synth.md` and `docs/llm/building-synths.md`.
- No project `run` skill exists for this repo yet — this session's browser-driven testing worked (cached Playwright + Chromium via npx cache), but a proper project skill would make future verification faster and more reliable. Worth generating one (`/run-skill-generator`) next time browser testing is needed.
- No automated test suite exists — all verification this/past sessions has been `svelte-check` plus manual/scripted browser smoke tests.

## Known issues
- `/add_track` with no explicit name still defaults to base name `"track"` (not `"track_1"`-style) — pass `name=` explicitly.
- The stereo delay's `stereoOffset` isn't exposed as a runtime param.
- Command-router name collisions between a track and a processor sharing the same name remain unguarded.
- `NLLCSampler`'s `_loadAll()` is fire-and-forget/unawaited — a trigger before a slot finishes loading silently no-ops rather than queuing.
- `/track_1 synth=...` (via the command router) only forwards the type, not extra constructor options — those still require creating the track fresh via `/add_track`.
- `splitCommands` (multi-command-per-line) assumes no param value contains a literal `/`; none currently do, but a value that did (e.g. a future file-path param) would be mis-split into extra bogus commands. Documented as a known limitation in `docs/llm/overview.md`.
- Changing `/clock num_beats=` while the engine is running can shift where the current loop boundary falls mid-flight — an accepted live-coding wrinkle rather than a bug, but worth knowing if an audible glitch shows up.
