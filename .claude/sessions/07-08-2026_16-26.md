## Project overview
NLLC is a SvelteKit + Web Audio live-coding music environment. Object model:
`NLLC` (top-level owner) → `clock: NLLCClock`, `master`/`tracks: NLLCTrack[]`
(each wrapping a `.source` synth)/`buses: NLLCChannel[]` (new — plain channels
with no synth, existing purely as shared send destinations),
`processors: NLLCProcessor[]`, `modulators: NLLCModulator[]` (e.g.
`NLLCLFO`), `patches: NLLCPatch[]`. Every channel (track, bus, or master) now
has a `sends` array rather than a single fixed destination — `out=` replaces
all of them with one, `add_send=`/`remove_send=` manage several
simultaneously, each with its own rampable gain. Source code is organized
with base classes at the `nllc-src/` root and non-base synth/processor/
modulator implementations in matching `synths/`/`processors/`/`modulators/`
subfolders. A project-specific `run` skill now exists for fast headless
browser smoke-testing of console commands. `docs/` (user/dev/llm tiers) is
fully in sync with all of the above.

## Open questions and next steps
- Wire up `Ollama()` to translate natural language into the command
  vocabulary — still the single biggest unbuilt piece of the project's
  stated premise.
- **Mono/stereo architecture** (discussed this session, not implemented):
  nothing currently locks the project into stereo-only. The one hard
  commitment is `NLLCChannel`'s `StereoPannerNode` (always 2-channel
  in/out) — everything else (`GainNode`-based signal path, the new sends
  model) is channel-count agnostic. Future mono channels or L/R-targeted
  sends would be additive: make the panner optional/pluggable per channel,
  and give `addSend` an optional "target channel" that interposes a
  `ChannelSplitterNode`/`ChannelMergerNode` pair instead of connecting
  straight into `destination.input`. Not scheduled — flagged for whenever it
  becomes relevant.
- Event/melody generation via modulators or patches remains deferred (needs
  an "event input" concept on `NLLCSynth` that doesn't exist yet — needs its
  own design discussion, don't build speculatively).
- Real harmonic logic: `nllc.harmony` is still a passthrough (chromatic
  scale). No `/harmony` command yet to change `root`/`scale` at runtime.
- Synth-level runtime params (e.g. `NLLCOscSynth.waveform`) still aren't
  exposed through `channelCommand`/`applyParams` the way processor/modulator
  params are — only settable via `/add_track synth=... waveform=...` at
  creation time.
- Modulator/patch/send UI is console-only (no mixer controls) — by design/
  scope choice, not a bug.
- Send routing has no cycle detection beyond the trivial self-send guard —
  a longer cycle (bus A → bus B → bus A) isn't caught; native Web Audio
  cycles are only well-defined with a `DelayNode` somewhere in the loop.
- Rhythm-context tooling (subdivision/grid/swing, euclidean rhythms,
  step-string parsers) and a per-cycle generation hook on the clock remain
  unbuilt (floated in earlier sessions).
- No automated test suite exists — verification is `svelte-check` plus the
  new `run` skill's console-output smoke checks (no live-audio assertions
  possible in this sandbox — see Known issues).

## Known issues
- This sandbox's headless Chromium does not render real-time audio
  (a known-audible track's level meter reads 0%; native `AudioParam` ramps
  never progress `.value` on live read-back). Doesn't affect the `run`
  skill's command-router smoke-testing (console text output only); use
  `OfflineAudioContext` batch-rendering if audio automation correctness
  itself needs verifying.
- Ramping/deferred (`at=`) scheduling on a multi-node param (`NLLCDelay`'s
  `time`/`feedback`) only animates the "primary" (L-side) node directly —
  unchanged, pre-existing limitation.
- `/add_track`/`/add_bus` with no explicit name default to base names
  `"track"`/`"bus"` (not `"track_1"`-style) — pass `name=` explicitly.
- The stereo delay's `stereoOffset` isn't exposed as a runtime param.
- Command-router name collisions between a track/bus/processor/modulator
  sharing the same name remain unguarded (each kind de-duplicated only
  within its own namespace).
- `NLLCSampler`'s `_loadAll()` is fire-and-forget/unawaited — a trigger
  before a slot finishes loading silently no-ops.
- `/track_1 synth=...` (via the command router) only forwards the type, not
  extra constructor options — those still require creating the track fresh
  via `/add_track`.
- `splitCommands` (multi-command-per-line) assumes no param value contains a
  literal `/`; none currently do, but a value that did would be mis-split.
- Changing `/clock num_beats=` while the engine is running can shift where
  the current loop boundary falls mid-flight — an accepted live-coding
  wrinkle rather than a bug.
