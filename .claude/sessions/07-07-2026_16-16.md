## Project overview
NLLC is a SvelteKit + Web Audio live-coding music environment. Core DSP/scheduling engine lives in `src/lib/scripts/nllc-src/`: `NLLC` (top-level owner: audioContext, clock, master, tracks, processors, and the `SYNTH_TYPES`/`PROCESSOR_TYPES` registries + factories), `NLLCClock` (setTimeout-based lookahead scheduler treating synths/channels/processors uniformly as "units"), `NLLCChannel`/`NLLCTrack` (fader/pan/insert-chain, with a track adding a swappable `.source` synth), `NLLCSynth` → `NLLCOscSynth`/`NLLCSampler`, `NLLCProcessor` → `NLLCReverb`/`NLLCDelay`, plus `NLLCEvent`/`NLLCAutomationEvent` as the two schedulable data shapes and `taper.js` for the fader's perceptual gain curve. `commands.js` is a closure-based `/name key=val` router giving full lifecycle control (create/remove tracks & processors, gain/pan, attach/bypass/remove effects, swap synth type, start/stop a track, list all tracks). The Svelte UI (`code-editor/+page.svelte` + `CodeEditor`/`Mixer`/`MixerChannel`/`Transport`/`CollapsedRail`) is a thin, polled read/write view directly on the live `NLLC` object's real Web Audio nodes — console and mixer are two UIs on one shared state, not separate stores. `Ollama()` remains an empty, unwired stub. As of this session, the project now has a full three-tier `docs/` tree (user/dev/llm) and the entire engine + key UI components are documented inline as well as externally; this documentation work was itself the whole session, so no engine/UI behavior changed (confirmed via `svelte-check`, no functional edits made).

## Known issues
- All previously-known issues are unchanged (no source behavior was modified this session, only comments/docs added):
  - `/add_track` with no explicit name still defaults to base name `"track"` (not `"track_1"`-style) — pass `name=` explicitly.
  - The stereo delay's `stereoOffset` isn't exposed as a runtime param.
  - Command-router name collisions between a track and a processor sharing the same name remain unguarded.
  - `NLLCSampler`'s `_loadAll()` is fire-and-forget/unawaited — a trigger before a slot finishes loading silently no-ops rather than queuing.
  - `/track_1 synth=...` (via the command router) only forwards the type, not extra constructor options (e.g. `waveform=`) — those currently require creating the track fresh via `/add_track`. Documented explicitly in `docs/user/commands.md` and `docs/dev/creating-a-synth.md` this session so it's no longer just tribal knowledge.
