# Write documentation for the project
You will create or update documentation files for the project.

## Instructions
All documentation will be created in the folder `docs`. All documentation will be in md format with examples.

Start by ingesting the project if it has not already been done, and then reading the existing documentation if it exists. You will be seeing what is missing in the existing documentation.

1. User documentation
Create in `docs/user`. This is documentation directed for the user only. So a tutorial, as well as a detailed list of commands and all avaiable objects.

2. Developer documentation
Create in `docs/dev`. This documentation is for developers only. You will need to provide detailed and exampled documentation of the project's architecture (both interface and source code), and overview of the source code. You will also provide a detailed set of tutorials for modify things (for example, creating your own synth, creating your own processor, modulator, adding new commands etc.).

3. LLM context
Create in `docs/llm`. This documentation is for LLMs only. A summary and overview of the project, and also different contextual summaries for things like buiding new synths, building new processors, modulator, adding commands etc. This can be concise in order to make best use of an LLM's contextual window.

4. Comment code base
Make sure that all of the source code is commented adequately.

5. README
Finally, update the project's `README.md` file.
